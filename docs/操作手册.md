# CutoverFlow 操作手册

## 管理员准备
登录后先建部门，再创建编制员、切换指挥员、执行员和核验员。初始各岗位角色可按实际职责分配；全范围管理员也受业务指派约束。人员停用和权限撤销即时生效，运行中变更人员可能使任务无法推进，请在运行前核对。
## 编制一份方案
进入“切换方案”新建草稿，填写编号、应用、影响范围、继续/回退判定和恢复验收依据，指定与本人不同的指挥人。编号与部门建后不变。创建至少一项任务；每项填写执行、核验、预计时长、步骤、标准和回退。前置任务从同一方案已存在的任务选择，可编辑依赖组成分支汇合，不能循环。
删除任务前先解除后继任务对它的引用。无提交历史的草稿可以删除；已提交后即使退回仍保留方案与事件。
## 放行与演练
编制员提交后由指定指挥人登录，可退回或放行冻结。放行时重新核对全部人员权限和依赖图。冻结后不能修改；变更应新建另一编号重新审批演练。指挥人“启动运行”选择演练，填受控凭证和本地截止时间，最长48小时（系统参数可进一步缩短）。
## 执行与核验
执行人工作台打开运行。前置任务全部核验通过才出现开始按钮。开工后执行人登记实际证据提交，核验人使用自己的账号独立通过或失败。最终一项通过后指挥人核对整次依据并“验收运行”。同一基线已有验收演练才允许正式切换，正式运行的所有任务重新从未开始状态生成。
按钮根据最新权限和状态显示；隐藏按钮不是授权依据，接口重复检查。发生连接错误可保留同一窗口原内容重试；改变内容会被幂等冲突拒绝。记录变更后刷新并重开窗口。
## 失败、超时与回退
执行或核验失败后运行阻断。期限到达后不能继续开工、完成或通过，但仍可登记失败和启动回退。指挥人登记实际原因启动回退；已开始的任务（含失败任务）按依赖逆序恢复，未开始任务不列入补偿。
执行人登记回退依据，指定核验人通过后才能回退其前置任务；退回则重新执行并登记。原执行和失败状态不会覆盖。全部回退核验结束后指挥人填写实际恢复依据确认恢复。没有已开始任务的终止仍需要指挥确认，但无需编造任务恢复。
## 查询、报告与退役
方案列表支持编号/名称、状态、时间或编号排序及分页。详情保存历次运行。运行JSON报告包含基线、任务、执行、回退与最近500条事件，不含宣传文字。数据统计只统计本人数据范围；完整事件保存在数据库。方案无活动运行后由指挥人退役，历史可读且不能再启动。
