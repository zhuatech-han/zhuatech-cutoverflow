# CutoverFlow 部署与升级

知华科技（上海如静知华信息科技有限公司） · https://www.zhuatech.cn/ · 商业咨询微信 zhuatech / zhuatech2

## 环境
Docker Engine、Compose v2、Python3.10+；源码开发 Java21、Maven3.9、Node24.19.0/npm11、MySQL8.4。运行 `python3 scripts/init-env.py` 生成私有0600 `.env`，再 `docker compose up -d --build --wait`。已有文件拒绝覆盖，需自己检查环境。
初始化管理员admin密码为ADMIN_PASSWORD，无公开固定密码；12–72字节，包含大小写字母及数字。配置生成器只输出文件位置，密码不要写进日志或命令参数。
## 端口与服务
BIND_ADDRESS默认127.0.0.1、WEB_PORT默认8118；端口占用可改18118，不停止其他项目。MySQL及后端只在Compose网络内访问。后端依赖数据库健康，前端依赖后端健康；入口 `/api` 和 `/actuator/health` 由Nginx代理，SPA路由回退至index。
自运行后端使用DATABASE_URL、DATABASE_USER、DATABASE_PASSWORD、DATABASE_CATALOG及ADMIN_PASSWORD。数据库目录必须是实际数据库名；默认zhuatech_cutoverflow。正式数据库账号限制至该库必需权限。
## 正式网络
使用HTTPS入口，COOKIE_SECURE=true，独立强密码、访问限制、可信数据库证书及主机名验证。默认本地驱动sslMode=trust不验证证书链；正式连接按数据库可信CA设置验证。学习版没有分布式会话或集中限流，不直接用于大规模多租户运营。
后端与前端运行账号非root；构建镜像执行测试，不跳过。Maven缓存使用锁及依赖预取重试。禁止把.env、源码版本库、业务备份和node_modules/target放入镜像构建上下文。
## 备份、升级和恢复
备份MySQL全库及迁移历史、私有配置，放在受控位置并验证恢复。升级前在独立测试库还原备份；新增下一版本 `V数字__说明.sql`，不能改已经执行的V1/V2。Flyway启动校验和升级，JPA验证字段。依赖校验失败先核对版本及日志，不删真实数据卷处理问题。
会话保存在内存，后端重启后需重新登录，持久化方案、任务、运行和证据保留。部署者需为真实业务安排备份、恢复、访问、容量与可用性验证。
## 故障和清理
`docker compose ps` 核对服务健康，`docker compose logs backend` 核对迁移及异常，分享前脱敏。配置缺失、数据库目录不符或迁移冲突会阻止启动；端口占用改WEB_PORT。仅在明确可销毁的独立验收环境使用 `docker compose -p cutoverflow-check down --volumes`。不要用全局清理或删除真实业务卷。
